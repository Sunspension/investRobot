# Тесты консистентности данных

Этот набор тестов проверяет целостность и консистентность данных между различными компонентами торговой системы.

## Структура тестов

### 1. `test_data_consistency.py`
Основные тесты консистентности данных между компонентами:
- **Консистентность данных свечей** между `SignalManager` и `DataManager`
- **Консистентность данных сигналов** между различными компонентами
- **Поток данных через EventBus** и корректность событий
- **Консистентность данных портфеля** и API ответов
- **Потокобезопасность DataManager** при конкурентном доступе
- **Консистентность конвертации Money** и обратная конвертация
- **Структура данных событий** и их валидность

### 2. `test_model_data_integrity.py`
Тесты целостности данных в моделях:
- **Целостность модели Signal** и её полей
- **Целостность модели Money** и конвертации
- **Целостность TradingDependencies** и всех зависимостей
- **Целостность SessionStats** и статистики
- **Целостность DataManager** и снимков данных
- **Целостность данных событий** и их структуры
- **Целостность данных в SignalManager** и логическая консистентность
- **Целостность данных портфеля** и API ответов
- **Целостность лимитов риска** и их логика
- **Консистентность данных между компонентами**

### 3. `test_realtime_data_consistency.py`
Тесты консистентности данных в реальном времени:
- **Консистентность потока событий** через EventBus
- **Консистентность данных при конкурентном доступе** к DataManager
- **Консистентность снимков данных** во времени
- **Консистентность расчета силы сигнала** в SignalManager
- **Консистентность конвертации Money** в различных сценариях
- **Консистентность времени событий** и их порядок
- **Консистентность валидации данных** и обработка ошибок

### 4. `test_architecture_data_consistency.py`
Тесты консистентности данных между слоями архитектуры:
- **Консистентность слоя данных** и TradingDependencies
- **Консистентность слоя бизнес-логики** и SignalManager
- **Консистентность слоя представления** и DataManager
- **Консистентность событийно-ориентированной архитектуры**
- **Консистентность внедрения зависимостей**
- **Консистентность потока данных** между компонентами
- **Консистентность обработки ошибок** в различных слоях
- **Консистентность использования памяти** и ограничений
- **Консистентность при конкурентном доступе** к компонентам

### 5. `test_data_consistency_utils.py`
Утилиты для тестирования консистентности данных:
- **DataConsistencyChecker** - основной класс для проверки консистентности
- **ConsistencyCheckResult** - результат проверки консистентности
- **DataConsistencyLevel** - уровни проверки консистентности
- **Вспомогательные функции** для создания тестовых данных

## Уровни проверки консистентности

### BASIC
- Проверка наличия обязательных полей
- Проверка типов данных
- Базовая валидация

### STRUCTURAL
- Проверка структурной целостности данных
- Проверка логических связей между полями
- Проверка диапазонов значений

### LOGICAL
- Проверка логической целостности данных
- Проверка бизнес-правил
- Проверка математических соотношений

### TEMPORAL
- Проверка временной целостности данных
- Проверка актуальности данных
- Проверка временных последовательностей

### COMPLETE
- Полная проверка всех аспектов консистентности
- Комплексная валидация данных
- Проверка всех зависимостей

## Запуск тестов

```bash
# Запуск всех тестов консистентности
pytest tests/test_data_consistency.py tests/test_model_data_integrity.py tests/test_realtime_data_consistency.py tests/test_architecture_data_consistency.py -v

# Запуск конкретного теста
pytest tests/test_data_consistency.py::TestDataConsistency::test_candle_data_consistency -v

# Запуск с подробным выводом
pytest tests/test_data_consistency.py -v -s

# Запуск с покрытием кода
pytest tests/test_data_consistency.py --cov=robotlib --cov=visualization
```

## Примеры использования

### Проверка консистентности данных свечи
```python
from tests.test_data_consistency_utils import DataConsistencyChecker, DataConsistencyLevel

checker = DataConsistencyChecker(event_bus)
candle_data = {
    'time': datetime.now(),
    'open': 1000.0,
    'high': 1010.0,
    'low': 990.0,
    'close': 1005.0,
    'volume': 1000
}

result = checker.check_candle_data_consistency(candle_data, DataConsistencyLevel.COMPLETE)
print(f"Consistent: {result.is_consistent}")
print(f"Errors: {result.errors}")
print(f"Warnings: {result.warnings}")
```

### Проверка консистентности DataManager
```python
data_manager = DataManager()
# ... добавление данных ...

result = checker.check_data_manager_consistency(data_manager, DataConsistencyLevel.COMPLETE)
print(f"DataManager consistent: {result.is_consistent}")
```

### Комплексная проверка
```python
results = checker.run_comprehensive_check(data_manager)
summary = checker.get_summary_report()
print(f"Consistency rate: {summary['consistency_rate']:.2%}")
print(f"Total errors: {summary['total_errors']}")
print(f"Total warnings: {summary['total_warnings']}")
```

## Критерии качества

### Консистентность данных
- ✅ Все обязательные поля присутствуют
- ✅ Типы данных корректны
- ✅ Значения в разумных пределах
- ✅ Логические связи между полями соблюдены
- ✅ Временные последовательности корректны

### Производительность
- ✅ Тесты выполняются быстро (< 1 секунды на тест)
- ✅ Память используется эффективно
- ✅ Конкурентный доступ безопасен
- ✅ Нет утечек памяти

### Надежность
- ✅ Обработка ошибок корректна
- ✅ Валидация данных работает
- ✅ Система устойчива к некорректным данным
- ✅ Восстановление после ошибок возможно

## Расширение тестов

### Добавление новых проверок
1. Создайте новый метод в `DataConsistencyChecker`
2. Добавьте соответствующий тест
3. Обновите документацию

### Добавление новых уровней проверки
1. Расширьте `DataConsistencyLevel`
2. Обновите логику проверок
3. Добавьте тесты для нового уровня

### Добавление новых типов данных
1. Создайте метод проверки для нового типа
2. Добавьте тесты
3. Интегрируйте в комплексную проверку

# Лимитирование запросов и Backoff

В проекте реализованы:
- Token Bucket лимитер для ограничений по RPS (частоте запросов)
- Экспоненциальный backoff с джиттером при переподключении стримов

## Конфигурация через .env

```env
# Лимиты для GET-запросов (market_data, operations, users, instruments и т.п.)
TCS_RATE_GET_RPS=8
TCS_RATE_GET_BURST=16

# Лимиты для POST-запросов (размещение/отмена ордеров)
TCS_RATE_POST_RPS=2
TCS_RATE_POST_BURST=4
```

- Параметры считываются в `config_data/config.py` и передаются в `TinkoffAPIClient` через `APIClientFactory`.
- По умолчанию используется 8 rps (burst 16) для GET и 2 rps (burst 4) для POST.

## Как работает Token Bucket

- Имеется «ведро» ёмкостью `capacity` токенов.
- Каждую секунду в ведро добавляется `fill_rate_per_sec` токенов (до предела `capacity`).
- Перед выполнением запроса берётся 1 токен.
- Если токенов нет — выполнение приостанавливается до накопления токенов.

В проекте реализовано в `robotlib/utils/rate_limiter.py` (класс `TokenBucket`).

## Экспоненциальный backoff с джиттером

Используется при переподключении стрима в `MarketDataStream`:
- Базовая задержка `base=0.5s`, максимум `max=30s`.
- Задержка растёт как `base * 2^retries`, но ограничена `max`.
- Применяется «полный джиттер»: финальная задержка — случайное значение в диапазоне `[0, delay]`.

Реализация функции вычисления задержки — `robotlib/utils/backoff.py` (`compute_backoff_delay`).

## Примеры

### Пример 1: Ужесточить лимиты в проде
```env
TCS_RATE_GET_RPS=5
TCS_RATE_GET_BURST=10
TCS_RATE_POST_RPS=1
TCS_RATE_POST_BURST=2
```

### Пример 2: Ослабить лимиты для offline загрузки исторических данных
```env
TCS_RATE_GET_RPS=12
TCS_RATE_GET_BURST=24
# POST можно оставить как есть
```

## Где применяется
- `TinkoffAPIClient`: перед каждым сетевым вызовом выполняется `await limiter.acquire()`
- `MarketDataStream`: при ошибках стрима — реконнект с backoff, логирование попыток

## Рекомендации
- Настраивайте лимиты исходя из тарифов API и частоты ваших задач.
- Для нескольких аккаунтов учитывайте суммарную нагрузку.
- Логи помогут понять, не упираетесь ли в лимитер (задержки перед вызовами).
